## 6. Recall latency at scale

Script: `scripts/recall-latency.ts` (raw JSON in `docs/audit/2026-10-20-recall-latency.json`).

```powershell
npx tsx scripts/recall-latency.ts
```

| Memories | Samples | p50 | p95 | Mean |
|---:|---:|---:|---:|---:|
| 1,000 | 150 | 1.61 ms | 2.36 ms | 1.72 ms |
| 10,000 | 150 | 24.11 ms | 26.68 ms | 24.47 ms |

Method: file-backed SQLite in WAL mode, 50 distinct queries × 3 repetitions per size, half with a target file, half without; 10 warm-up queries discarded; `backfill: false`. This is **engine-level recall**, not CLI end-to-end.

The 10k p95 (26.68 ms) is under the 50 ms target, but the 15× jump from 1k to 10k is a scaling warning: the graph stream and candidate loading are not yet bounded tightly enough.

## 10. Known debt carried into Phase 1

1. `src/search/hybrid-rrf.ts` uses default `f.rank`, the global UNION lacks the `global_db.memories_fts` qualifier, RRF `k=60` is hardcoded, and there are no per-stream weights.
2. `src/search/backfill.ts` writes deterministic hash vectors by default; the "vector" stream is lexical n-grams unless `FASTR_EMBEDDINGS_MODEL=1`.
3. `src/mcp/server.ts` reports the server name `@fastrsoft/fastrmemory` while the package is `@atifjubaer/fastrmemory`.
4. 60 legacy test rows remain in `~/.fastr/global.db`; cleanup is manual and confirmed-only.
5. Production dependencies carry 6 audit advisories through the optional model stack.
6. Documentation is limited to architecture, specification, benchmark, publishing, registry, and audit material; historical prompt and transcript archives were removed from the tree on 2026-10-20.
