## Corpus

The corpus is generated by [`src/bench/corpus.ts`](src/bench/corpus.ts) and committed as [`bench/corpus.json`](bench/corpus.json). It contains **120 memories** and **240 queries** across six categories:

| Category | Cases | What it tests |
| :--- | ---: | :--- |
| Exact keyword | 48 | Direct term and file-path matches |
| Semantic paraphrase | 48 | Same intent, different wording |
| File-scoped trap | 32 | An error trap attached to the file being edited |
| Bi-temporal superseded | 32 | The current fact must outrank the superseded one |
| Multi-hop | 16 | A fact reachable through a file or entity link |
| Long-horizon | 16 | An old memory that must survive many newer inserts |

The split is fixed by the generator: **80% train, 20% holdout**. Retrieval weights were chosen on the train split only; the holdout was evaluated only with the frozen configuration, and the rerun on committed code reproduced the same accuracy. `bench/corpus.json` is generated from a fixed seed, so the case text and expected IDs are reproducible.

## What is measured

Each case calls `searchMemories()` with `limit: 5`, a **250-token context budget**, and the case's target file when one is defined. Rank is taken from the returned ranked memories; token cost is measured from the compact prompt text. Latency wraps only the in-process search call and excludes Node startup, model download, and model load.

`Hit@k` is the share of cases whose expected memory appears in the top `k`. `MRR` is the mean reciprocal rank. `nDCG@10` uses the single relevant target per case. Confidence intervals are bootstrap 95% intervals over cases.

## Ablations

All ablations use the same corpus, split, and 250-token budget.

| Configuration | Train Hit@1 | Holdout Hit@1 | What changed |
| :--- | ---: | ---: | :--- |
| BM25-only | 79.7% | 77.1% | No vector or graph stream |
| BM25 + MiniLM | 96.4% | 95.8% | Title + module semantic vectors |
| BM25 + file graph | 79.7% | 77.1% | Graph stream, no vectors |
| Triple-stream + conditional trap boost | 96.4% | 95.8% | Production defaults |
| Hash triple-stream, no trap boost | 81.8% | 77.1% | Trap multiplier disabled (hash run) |

The graph stream does not improve Hit@1 on this corpus because every file-scoped case already retrieves its target. It is retained for real repositories where file links connect memories that share no query terms. The conditional trap boost is neutral on hash vectors; it is scoped so the multiplier applies only in trap-relevant context.

## Retrieval defaults measured here

- RRF `k = 20`.
- Stream weights: BM25 `1.0`, MiniLM vectors `3.0` when semantic vectors are present, hash vectors `1.0`, graph `1.0`.
- Error-trap multiplier `2.0x` only when the query has trap intent or is scoped to a file linked to the trap.
- Verified-memory multiplier `1.25x`.
- Context budget `250` tokens; ranked result objects keep full memory content.

## Caveats

1. **Synthetic corpus.** These cases are generated for this repository, not SWE-bench, LongMemEval, or LoCoMo. They test defined retrieval behaviors, not general coding-agent competence.
2. **The static dump is simulated; the external baselines are separate.** The static-dump row is a simulation implemented in `src/bench/harness.ts` and must never be cited as an external project's result. The pinned MiniSearch and MCP memory baselines are measured separately in [`docs/EXTERNAL_BASELINE.md`](docs/EXTERNAL_BASELINE.md).
3. **Small holdout.** Forty-eight holdout cases give a wide Wilson Hit@1 interval (86.0-98.9%). Treat the point estimate as directional, not precise.
4. **Token counts are estimates** from `estimateTokens()`, not a tokenizer-exact count.
5. **Latency is in-process.** CLI cold start is measured separately in `docs/audit/2026-10-20-baseline.md`.
6. **MiniLM is optional.** The package works offline with hash vectors; semantic results require the optional model.
7. **The old 12-case suite is a smoke test.** It is not the headline benchmark and is not comparable to the 240-case corpus.

## Reproduce

```bash
npm ci

# Semantic run (downloads the optional MiniLM model on first use)
npx tsx scripts/eval-bench.ts --split all --embeddings minilm --out bench/results/minilm.json

# Offline run
npx tsx scripts/eval-bench.ts --split all --embeddings hash --out bench/results/hash.json

# Legacy 12-case smoke test
npx tsx scripts/capture-bench.ts
```

Accuracy columns should reproduce on any machine with the same corpus. Latency will vary.
